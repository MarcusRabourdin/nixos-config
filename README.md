# NixOS configuration

Personal NixOS configuration, managed as a flake with home-manager.

- **OS**: NixOS 26.05
- **Display**: X11 (Xorg) + LightDM
- **Window manager**: i3
- **Shell**: zsh
- **Terminal**: Alacritty
- **Editor**: Helix (LSP: TypeScript, C# via Roslyn)

## Repository layout

```
flake.nix                    # Entry point: inputs + one nixosConfiguration per machine (mkHost)
flake.lock                   # Pinned versions of nixpkgs and home-manager
home.nix                     # home-manager entry point for user "blue"
hosts/
  <hostname>/
    configuration.nix        # System configuration of this machine
    hardware-configuration.nix  # Generated by nixos-generate-config, NEVER copy between machines
dotfiles/                    # home-manager modules (one per program)
  git.nix helix.nix i3.nix term.nix zsh.nix
packages/
  core.nix                   # Everyday CLI / desktop tools
  currently_usefull.nix      # Dev toolchains and apps used at the moment
bin/                         # Personal scripts, added to $PATH (see bin/bin.md)
  bluetooth/ hdmi/ pk/
```

## Where the config lives

The repository is cloned in **`/etc/nixos`**:

- `nixos-rebuild` uses `/etc/nixos/flake.nix` by default;
- `$CONFIGURATION_PATH` points to it (defined in `home.nix`);
- home-manager creates a **`~/config` → `/etc/nixos`** symlink;
- the `bin/*` folders are added to `$PATH` from there, so scripts can be edited without rebuilding.

`/etc/nixos` must be owned by the user (`blue`), otherwise git refuses to work in it (`dubious ownership`).

## Daily usage

| Action | Command |
|---|---|
| Rebuild, commit and push | `nrs` |
| Build without applying (test) | `nixos-rebuild build --flake .` |
| Apply | `sudo nixos-rebuild switch --flake .` |
| Format all Nix files | `nix fmt` |
| Update nixpkgs / home-manager | `nix flake update` then rebuild |
| Roll back to the previous generation | `sudo nixos-rebuild switch --rollback` (or pick it in the boot menu) |

`nrs` = `cd $CONFIGURATION_PATH && git add -A && sudo nixos-rebuild switch --flake . && git commit && git push`.

## Packages

Package lists are in [`packages/`](packages/). Programs that have their own home-manager module (git, helix, alacritty, zsh, i3) are installed by that module in `dotfiles/`, not in the lists.

Unfree packages are allowed (`nixpkgs.config.allowUnfree`).

## Install on another PC

### 0. Install NixOS

Install NixOS from the official ISO (the graphical installer is fine).
**Create the user `blue`** during the installation: it will already have a password.

The installer generates `/etc/nixos/configuration.nix` and `/etc/nixos/hardware-configuration.nix`. Keep them, they are needed below.

### 1. Get git

```bash
nix-shell -p git
```

### 2. Clone the repository in /etc/nixos

```bash
sudo mv /etc/nixos /etc/nixos.install
```

```bash
sudo git clone https://github.com/MarcusRabourdin/nixos-config /etc/nixos
```

```bash
sudo chown -R blue:users /etc/nixos
```

```bash
cd /etc/nixos
```

### 3. Create the machine folder

Replace `<hostname>` with the name of the new machine (e.g. `laptop`).

```bash
mkdir hosts/<hostname>
```

```bash
cp /etc/nixos.install/hardware-configuration.nix hosts/<hostname>/
```

```bash
cp hosts/main-nixos/configuration.nix hosts/<hostname>/
```

> ⚠️ Never reuse the `hardware-configuration.nix` of another machine: it contains its disk UUIDs and the system would not boot.

### 4. Adapt `hosts/<hostname>/configuration.nix`

Compare it with `/etc/nixos.install/configuration.nix` and check:

- [ ] `networking.hostName = "<hostname>";`
- [ ] **Bootloader**: `systemd-boot` only works in UEFI. If the installer generated `boot.loader.grub…`, the machine boots in BIOS mode: keep the installer's bootloader settings.
- [ ] **`system.stateVersion`**: use the value generated by the installer, **not** the one of `main-nixos`. Never change it afterwards.
- [ ] `time.timeZone`
- [ ] Machine-specific settings to keep or remove: Bluetooth `ControllerMode = "bredr"` (disables BLE), `programs.appimage`.

### 5. Declare the machine in `flake.nix`

```nix
nixosConfigurations = {
  main-nixos = mkHost "main-nixos";
  <hostname> = mkHost "<hostname>";
};
```

### 6. Add the new files to git

A flake ignores untracked files: without this, the build fails with `path ... does not exist`.

```bash
git add -A
```

### 7. Build and switch

Flakes are not enabled yet on a fresh install, hence the `--option`. The first time, the configuration name must be given explicitly (`#<hostname>`).

```bash
sudo nixos-rebuild switch --flake .#<hostname> --option experimental-features 'nix-command flakes'
```

If the user `blue` was **not** created during the installation, give it a password now (the config creates it without one):

```bash
sudo passwd blue
```

### 8. Reboot

Required: the hostname changes, and X11 refuses to open new windows in a session started with the old hostname.

```bash
sudo reboot
```

Log in as `blue`. From now on, `nrs` (or `sudo nixos-rebuild switch --flake .`) is enough: the configuration is selected from the hostname.

### 9. Save the new machine

Set up GitHub authentication (`gh auth login`, or an SSH key), then:

```bash
git commit -m "hosts: add <hostname>"
```

```bash
git push
```

You can delete `/etc/nixos.install` once everything works.

## Good to know

- **Changing the hostname** → reboot, otherwise new windows can't open.
- **Upgrading NixOS** (e.g. 26.05 → 26.11): change `nixpkgs.url` **and** the home-manager `url` together, `nix flake update`, build, switch, then reboot. Fix every `evaluation warning: ... has been renamed`.
- **`stateVersion`** (system and home) stays at the version of the first install. It is not the current NixOS version.
- **`home.sessionVariables` / `home.sessionPath`** are only loaded at login: log out and back in after changing them.
- **"Git tree is dirty"** is only a warning: the build uses uncommitted changes, but new files must be `git add`-ed.
- **Helix**: check language servers with `hx --health <language>`.
